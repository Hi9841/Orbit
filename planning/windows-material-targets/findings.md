# Findings

- Loop pinned source `.tools/upstream-loop.zip` includes `PreviewView.swift`, which draws `.hudWindow` material with an accent gradient at `previewBackgroundAccentOpacity`; `Defaults+Extensions.swift` sets that opacity to `0.1` and blur to enabled. `RadialMenuView.swift` uses a HUD material ring, quinary borders, and an accent direction segment. Repository: https://github.com/mrkai77/Loop .
- Orbit `src/preview.rs` currently applies the saved `preview_opacity` as accent wash strength. Saved and default value 255 turns the entire plate blue. `src/platform.rs::color_key_pixel` flattens every pixel with alpha at least 128 to opaque, so bitmap alpha cannot supply translucency.
- Microsoft documents `SetLayeredWindowAttributes` with `LWA_ALPHA` and `LWA_COLORKEY` for window-wide translucency and a transparent color key: https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setlayeredwindowattributes .
- Microsoft says `DwmEnableBlurBehindWindow` no longer produces blur starting with Windows 8: https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/nf-dwmapi-dwmenableblurbehindwindow . Windows 11 transient Acrylic is documented but depends on a separate backdrop path and is not proven compatible with the current color-key popup: https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type .
- `src/platform.rs::ensure_target` checks only window existence and identity. `ignore_fullscreen` defaults and saves as false, and the fullscreen check in `apply_frame_action` returns `Ok(())` after target acquisition. Existing `is_fullscreen` detects borderless monitor-filling windows.
- The prior live screenshot `.tools/desktop-present-live.png` is a red-capable visual record: it shows the opaque blue plate. The user stopped further desktop E2E tests, so only source and build verification are permitted for now.
